# sec-jwt-claims

## 题面

接口只校验签名不校验声明，别的租户的令牌也能进来，过期令牌还能再用一会儿：令牌拆分不校验段数，两段令牌也被接受；拆分用标准 Base64 解码，URL 安全字符解码失败或错位；签名校验不校验算法字段，随令牌自报算法选择；算法为 none 时直接返回通过；时间校验只看到期时间不看生效时间，未来令牌可用；时钟偏移作用于整个有效期，偏移量被重复放大；受众校验只比较第一个受众，数组里的其他值被忽略；签发者用前缀比较，伪造签发者可通过；汇总校验任一项失败仍返回通过，错误被吞掉；批量校验复用解码后的声明，后一个令牌用前一个令牌的受众。jwtc/claims.py 是核心，tests/test_claims.py 15个红。要修的是：按上面的顺序把 10 个缺陷逐个修掉。

## 运行方式与初始状态

把终端切到仓库根目录，运行下面这一行：

```text
python -m pytest tests -q
```

首次运行时，汇总行必须正好是 15 failed，不能出现 collection error、import error 或 syntax error。十五个失败都应来自尚未实现的 NotImplementedError；若失败数量不是 15 或出现 error，说明环境或测试文件异常，不应继续。

## 契约与约束

- 所有时间由调用方显式传入，不读取系统时钟，不使用随机数，不联网。
- 只使用标准库 json、base64、hmac、hashlib 与 pytest；离线运行，不安装外部依赖。
- 签名算法固定为 HS256，不得根据令牌头部的自报算法扩展白名单；none 必须拒绝。
- Base64URL 使用 URL 安全字母且不带填充；令牌必须恰好三段，头和载荷都必须是 JSON 对象。
- 时间窗口按 docstring 的边界公式判定，exp 为开边界，nbf 为闭边界；时钟容差上限为 60 秒，且只能对每个边界计算一次。
- 受众为字符串时精确比较，为数组时必须包含期望受众；签发者必须与白名单全等。
- validate_claims 必须保留逐项布尔结果，任何失败都不得被 overall 结果掩盖。
- claims_batch 必须为每枚令牌重新解析和校验，不能复用上一枚令牌的头部、载荷、受众或签名。
- tests/test_claims.py 不可修改、删除、跳过或缩减；只允许修改 jwtc/claims.py。

## 验收覆盖面

验收用例共十五个。前十个逐项锁定题面的十类问题，后五个分别锁定合法令牌、篡改、过期、受众错配和批量一致性。场景覆盖段数、Base64URL 字母、算法混淆、none、nbf 与 exp 边界、容差放大、受众数组、签发者前缀、错误吞掉以及批量状态串用。
